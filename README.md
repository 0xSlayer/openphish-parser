# OpenPhish Parser

Учебный проект по сбору, очистке и анализу данных OpenPhish в рамках самостоятельного задания по теме «Сбор, очистка и обработка данных».

## О проекте

Программа периодически получает публичный список фишинговых URL OpenPhish, очищает полученные данные, проверяет записи на дубликаты и сохраняет новые URL в CSV-файл.

Сборщик настроен на:

* интервал между запросами — **5 минут**;
* продолжительность сбора — **1 час**;
* сохранение времени первого обнаружения URL сборщиком;
* исключение дубликатов внутри текущего набора данных;
* исключение URL, уже сохранённых во время предыдущих запросов.

Дополнительно реализован анализ статистики атакуемых брендов, опубликованной на главной странице OpenPhish.

```text

├── README.md
```

### `parser.py`

Основной сборщик данных.

Выполняет:

1. получение OpenPhish Community Feed;
2. очистку полученных строк;
3. проверку URL на дубликаты;
4. сравнение с ранее сохранёнными URL;
5. сохранение новых записей в CSV;
6. повторный запрос через заданный интервал;
7. завершение работы после истечения установленного периода.

В итоговой конфигурации:

```python
INTERVAL_SECONDS = 300
DURATION_SECONDS = 3600
```

То есть запрос выполняется каждые 300 секунд в течение 3600 секунд.

### `inspect_homepage.py`

Получает главную страницу OpenPhish и с помощью BeautifulSoup анализирует таблицу статистики атакуемых брендов.

Скрипт выводит текущие Top-3 targeted brands.

### `analyze.py`

Формирует итоговую сводку:

* время начала сбора;
* время окончания сбора;
* количество выполненных запросов;
* количество сохранённых URL;
* количество уникальных URL;
* количество дубликатов;
* Top-3 атакуемых бренда по агрегированной статистике главной страницы OpenPhish.

## Установка

Для проекта используется Python 3 и виртуальное окружение.

Создание виртуального окружения:

```bash
python3 -m venv .venv
```

Активация:

```bash
source .venv/bin/activate
```

Установка зависимостей:

```bash
pip install -r requirements.txt
```

Основные внешние библиотеки:

* `requests` — выполнение HTTP-запросов;
* `beautifulsoup4` — разбор HTML.

## Запуск сборщика

Обычный запуск:

```bash
python parser.py
```

Для одновременного вывода информации в терминал и сохранения журнала рекомендуется использовать Python без буферизации:

```bash
python -u parser.py | tee logs/collection_$(date +%Y%m%d_%H%M%S).log
```

Параметр `-u` отключает буферизацию стандартного вывода Python, благодаря чему сообщения сразу появляются в терминале и записываются через `tee` в лог.

Пример вывода:

```text
Parser started: 2026-09-01T16:01:04+03:00
Collection interval: 300 seconds
Collection duration: 3600 seconds

Collection: 1
Collected at: 2026-09-01T16:01:04+03:00
URLs in current feed: 300
Unique URLs in current feed: 300
Already saved URLs: 0
New URLs: 300
Saved to: data/openphish.csv
Waiting: 300 seconds...
```

При последующих запросах URL сравниваются с уже сохранёнными:

```text
Already saved URLs: 300
New URLs: 0
```

Если появляются новые URL, в CSV добавляются только ранее не встречавшиеся записи.

## Формат CSV

Результаты сохраняются в:

```text
data/openphish.csv
```

Формат:

```csv
url,collected_at
http://example.example/,2026-09-01T16:01:04+03:00
```

Поле `collected_at` означает время, когда URL был впервые обнаружен данным сборщиком.

Это не время первоначального обнаружения фишингового ресурса системой OpenPhish.

## Особенность текущей версии OpenPhish

В описании учебного задания предполагается наличие таблицы с данными:

```text
URL | атакуемый бренд | время атаки
```

На момент выполнения работы структура публичных данных OpenPhish отличается.

Публичный Community Feed предоставляет список URL без привязанного к каждой записи названия атакуемого бренда и времени атаки.

Поэтому в проекте используются два отдельных источника данных:

1. **OpenPhish Community Feed** — для получения и накопления фишинговых URL.
2. **Главная страница OpenPhish** — для получения агрегированной статистики Top Targeted Brands.

В связи с этим Top-3 брендов в данном проекте является агрегированной статистикой OpenPhish и **не является результатом классификации непосредственно 300 URL, сохранённых в `openphish.csv`**.

## Дедупликация

Проверка дубликатов выполняется на двух уровнях.

### Внутри текущего ответа OpenPhish

Используется множество `seen_urls`.

Если один URL несколько раз присутствует в полученном наборе данных, он обрабатывается только один раз.

### Между запросами

Перед сохранением программа читает ранее записанные URL из CSV и помещает их в множество `existing_urls`.

Новый URL записывается только при условии:

```python
if url not in existing_urls:
    new_urls.append(url)
```

Благодаря этому повторные запросы не создают дубликаты в итоговом CSV.
